# OGフォントの文字集合

`flake.nix` の `ogFonts` は Noto Sans CJK JP をこの2つのファイルだけから
サブセットして `og/static/fonts/NotoSansJP-{Regular,Bold}.ttf` を作る。
記事の title / description をコーパスにすることはしない。

記事をコーパスにすると、記事を1本追加するたびにフォントの中身 (= Nix の
ストアパス) が変わり、`og/` を触っていないのに OG Worker の再ビルドと
再デプロイが必要になる。その連鎖を切るために、必要な文字はここで固定する。

| ファイル             | 内容                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `charset-ranges.txt` | Unicodeレンジの一覧 (pyftsubset の `--unicodes` と同じ書式)。ASCII / ラテン / ギリシャ / 約物 / 通貨 / 数学記号 / 仮名 / 全角形 |
| `jisx0208-kanji.txt` | JIS X 0208 の第1・第2水準漢字 (区16-84) 6,355文字をコードポイント順に1行で並べたもの                                            |

`charset-ranges.txt` には **Noto Sans CJK JP が実際に持っている文字だけ**を
書く。未割り当てのコードポイント (`U+3040` など) や、フォントに無い文字
(絵文字や `✔` `☑`) を書いても豆腐が増えるだけで意味がない。`flake.nix` の
`ogFonts` が、書かれた全コードポイントがサブセットに入ったかをビルド時に
検査するので、フォントに無い文字を足すと `nix build .#og-fonts` が失敗する。

## 文字が足りなくなったら

集合に無い文字は豆腐 (□) として描画される。`tests/og_charset_test.ts` が
記事の `#+TITLE:` / `#+DESCRIPTION:`、`host.ts` のカード文言、`og/src` と
`og/test` の文字列リテラルを集合と突き合わせて、足りない文字を
コードポイント付きで落とす。

対処は次のどちらか。

1. `charset-ranges.txt` にその文字のレンジ (または `U+XXXX` 単体) を追記する。
   このファイルは `og/**` の下にあるので、追記すると OG CI が走り、
   広いサブセットで Worker が再デプロイされる
2. タイトルや説明からその文字を外す

`jisx0208-kanji.txt` は手で足さない。ここは「JIS X 0208 の漢字全体」という
固定の定義で、`tests/og_charset_test.ts` が EUC-JP から引き直した集合と
一致することを検証している (区1の記号である仝は漢字ではないので含まない)。

## フォントに実際に入ったかの確認

`og/test/font_coverage_test.gleam` が、第2水準の漢字2文字 (騙 / 燻) を
描いた画像のハッシュが異なることを確かめる。豆腐は字形を持たないため、
別々の漢字が別々のPNGになることは両方の字形がフォントに入っている証拠になる。
